# 测试报告：性能与验证

## 1. 测试原则

性能结论必须同时记录输入来源、分辨率、输出模式、线程数、阈值和采集方法。不能将纯 RKNN 吞吐、视频文件端到端吞吐、Camera 端到端吞吐混作同一个 FPS 指标。

`perf stat` 用于观察 CPU cycles、instructions、cache miss 等计数器；`perf record` 用于定位 CPU 热点。两者可能影响 V4L2 Camera 时序，因此正常吞吐以未挂 profiler 的重复运行结果为准。

## 2. 已验证性能

| 场景 | 条件 | 结果 | 含义 |
| --- | --- | --- | --- |
| 纯 RKNN | 6 worker，三核 NPU，固定输入 | 约 159 FPS (ReLU INT8 6线程) | NPU 推理吞吐上限，不含采集、预处理、后处理和输出 |
| 视频 + MPP | 1080p 视频文件，检测、RGA、MPP H.264 | 约 62 FPS | 完整编码输出，不含 RTMP 网络发送 |
| 视频 + RTMP | 1080p 视频文件，MPP H.264、FLV/RTMP | 约 56 FPS | 包含推流封装与网络路径 |
| Camera OpenCV baseline | 640x480 YUYV@30，6 worker，MPP-only，600 帧 | 28.380 FPS | 正常运行采样 |
| Camera DMA-BUF + RKNN fd | 640x480 YUYV@30，8 V4L2 buffers，6 worker，MPP-only，600 帧 | 27.840 FPS | 正常运行采样 |

Camera 两组吞吐接近，说明当前端到端 FPS 受 Camera buffer 生命周期、NPU/RGA/输出流水线等因素共同限制，DMA-BUF 的核心收益不是保证直接提高 FPS，而是减少 CPU 图像搬运。

## 3. DMA-BUF CPU 计数器对照

以下为 `perf stat` 的公平对照，条件为 640x480 YUYV@30、6 worker、600 帧、MPP-only：

| 指标 | V4L2 mmap + RKNN copy | DMA-BUF + RKNN fd | 变化 |
| --- | ---: | ---: | ---: |
| 端到端 FPS | 14.785 | 14.765 | -0.1% |
| task-clock / frame | 12.269 ms | 10.880 ms | -11.3% |
| cycles / frame | 17.832 M | 15.931 M | -10.7% |
| instructions / frame | 7.311 M | 6.436 M | -12.0% |
| cache-misses / frame | 103,441 | 102,117 | -1.3% |
| preprocess | 1.872 ms | 1.609 ms | -14.0% |
| rknn_input_set | 1.006 ms | 0 ms | 消除逐帧设置 |

该表的 FPS 仅表明 profiler 对 Camera 时序产生了干扰，不能替代第 2 节的正常运行吞吐。计数器对照仍说明 DMA-BUF + fd 降低了 CPU 输入路径工作量。

## 4. 历史视频阈值实验（非当前默认值）

早期在固定 1080p 视频、同一帧和当时模型条件下比较 `BOX=0.5/0.6/0.7`。该实验中，`BOX=0.6` 是检测质量与后处理开销的一个可接受折中：提高阈值会减少候选框并明显降低 NMS 时间，但可能漏掉低置信度目标。

**当前代码默认值不是 0.6，而是 `BOX=0.5`、`NMS=0.5`。** 当前 ReLU Camera 链路使用默认值以优先保证召回；只有复现上述视频实验或业务确认可接受漏检时，才通过 `--box-threshold 0.6` 显式启用。

历史测量中，候选框和 NMS 是 CPU 后处理热点；从 `BOX=0.5` 调整到 `0.6` 后，NMS 平均耗时约从 5.25 ms 降至 2.56 ms。该数据只说明该固定视频/模型上的参数敏感性，不能作为所有输入和模型的通用性能结论。

## 5. 验证结论与限制

- 结果图片/视频验证了 DMA-BUF 输入和 copy 输入的检测框一致性；
- DMA-BUF + RKNN fd 已消除显式 `pre_copy` 与逐帧 `rknn_input_set`；
- 当前输出侧仍包含 CPU 画框，尚非全链路零拷贝；
- `perf record --call-graph dwarf` 在该 UVC/V4L2 mmap 路径上可造成明显扰动甚至遗留 Camera 占用，热点结果须谨慎解读；
- USB Camera 重新插拔后 `/dev/videoN` 可能变化，应在运行前确认节点和格式能力。
