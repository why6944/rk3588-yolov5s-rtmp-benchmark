# YOLOv5s ReLU 模型精度验证报告

> **评估环境**：Ubuntu x86_64，RKNN-Toolkit2 2.3.2 PC simulator。
> **日期**：2026-10-25。

本报告比较同一份 ReLU ONNX 构建的未量化 RKNN 与 INT8 Normal RKNN。在 78 张未参与校准的图片上，mAP@0.5 从 0.547454 降至 0.531546，回退约 **1.59 个百分点**。这是模拟器量化回归结果，不是完整 COCO 成绩，也不是摄像头全链路测试。

## 1. 测试配置

| 条件 | 值 |
| --- | --- |
| 源模型 | `yolov5s_relu.onnx`，COCO 80 类，输入 640×640 |
| 未量化基线 | `do_quantization=False`；历史脚本称 `fp32`，不保证底层全部运算为 FP32 |
| INT8 版本 | INT8 Normal，`asymmetric_quantized-8`，channel quantization |
| 验证图片 | COCO128 排除 50 张与校准集内容哈希重叠的图片，保留 78 张 |
| 标签覆盖 | 559 个目标，65 个有标注类别；另外 15 类无标注 |
| 预处理 | BGR→RGB，直接 resize 到 640×640；mean=0，std=255 |
| 解码与去重 | 输出不重复执行 Sigmoid；候选阈值 0.001；class-aware NMS IoU=0.60 |
| AP 门槛 | IoU=0.50:0.05:0.95，共 10 个门槛 |
| P/R 门槛 | 置信度 ≥0.25、匹配 IoU ≥0.50，按类等权平均 |

### 1.1 为什么统计 65 类而不是 80 类

模型仍输出 COCO **80 类**分数，没有裁成 65 类；65 是这 78 张图片中实际出现的标注类别数。其余 15 类没有标注，AP 记为 **N/A**，不是 AP=0，也不参与本次平均。因此分母为 65，不能填零后改成除以 80。

这里的验证集是量化回归子集，不是官方 COCO test 集。“独立”只表示已排除校准重叠，尚未证明与模型预训练数据隔离；结果不能代表完整 COCO 80 类精度。

## 3. 离线评估流程

78 张图片全部参与统计，两种模型各逐图前向推理 78 次，不更新权重。所谓数据回放只走精度评估路径，不走摄像头、DMA-BUF、RGA、MPP、RTMP 的完整视频链路。

```text
图片及人工标注
  → BGR 转 RGB、resize 到 640×640
  → RKNN PC simulator 前向推理
  → YOLOv5 检测头解码、候选筛选、NMS
  → 逐图同类别 IoU 一对一匹配
  → 汇总全部图片，按类别和置信度计算 AP、mAP
```

校准集只用于 INT8 构建，正式评估已排除其 50 张重叠图。预测和标签都转换到 640×640 坐标系；这里直接 resize，没有使用 letterbox。

## 4. 指标计算方法

### 4.1 TP、FP 与 FN

同类别且 IoU 达标的预测才可匹配标注；一个预测和一个标注各最多匹配一次。本评估器在每张图、每个 IoU 门槛下按 IoU 降序去重分配匹配，再汇总预测、按置信度排序。匹配成功为 TP；未匹配预测为 FP；固定分数门槛下未被正确检出的标注为 FN。

固定置信度下，`Precision = TP / (TP + FP)`，`Recall = TP / (TP + FN)`。例如 INT8 的 person 类有 140 个标注，置信度 0.25 时 TP=82、FP=45、FN=58，P=64.57%、R=58.57%。

### 4.2 单类别 AP

将全部 78 张图片中同一类别的预测按置信度从高到低排列，依次累计 TP、FP，得到 PR 曲线。不是先算每张图片的 AP 再平均，也不是把 P 与 R 平均。

实现中先对 Precision 取单调包络，再在 Recall=0、0.01、…、1.00 共 101 个位置线性插值，用梯形积分求 AP。AP50 在匹配 IoU=0.50 时计算；AP50:95 则对 0.50～0.95 的 10 个 IoU 门槛求平均。person 的 INT8 AP50 为 65.46%，不等于上面的固定点 P 或 R。

当前端点和梯形积分约定下，部分完美检出的单目标类别可能得到 AP=0.995，而不是 1.000。它不代表漏掉了 0.5% 的目标。

### 4.3 mAP 与约 1.6 个百分点的回退

对 65 个有标注类别的 AP 等权平均：

```text
mAP50 = sum(AP50[c]) / 65
mAP50:95 = sum(AP[c, t]) / (65 × 10)
未量化 AP50 之和 ≈ 35.584524，除以 65 ≈ 0.547454
INT8   AP50 之和 ≈ 34.550476，除以 65 ≈ 0.531546
回退 = (0.547454 − 0.531546) × 100 ≈ 1.5908 个百分点
```

每类权重相同，不按该类目标数加权。65 类中 27 类 AP50 下降、22 类上升、16 类不变，变化相互抵消后总体回退约 1.59 个百分点；不是每类都下降 1.6。若用相对百分比口径，下降约为 2.9%，不要与百分点混写。原脚本 float32 汇总与逐类 JSON 复算可能存在末位浮点差异。

马、蛋糕、滑雪板分别只有 2、1、1 个标注，不能把较大 AP 波动推广为普遍量化敏感性。蛋糕在置信度 0.25 下两版都检出了唯一目标，FN 仍为 0，但 FP 从 1 增至 2；AP 下降不等于同样比例的漏检。

## 6. 验证结论与限制

本次 ReLU INT8 Normal 的 mAP@0.5 回退约 1.59 个百分点，mAP@0.5:0.95 回退约 2.01 个百分点。54 组统计回归测试通过，两组各 78 张图片的预测缓存、匹配和指标复算通过，总体数值与历史记录一致。

当前数据类别分布不均、样本较少，未给出置信区间；未确认预训练数据隔离。评估沿用自定义 YOLO 风格实现，没有直接使用官方 COCOeval，maxDets、crowd/ignore、面积过滤、匹配及插值汇总规则不同会改变分数，不能对外宣称为完整 COCO 榜单精度。

定位下降时，应检查同图预测的分数、框位置和类别混淆；怀疑 NMS 要补存 NMS 前候选，现有缓存只有 NMS 后结果。必要时做 RKNN 逐层误差分析，再用更大业务验证集验收。AP 下降本身不能证明校准集缺该类；COCO 也没有安全帽类别。
