# 目录结构与复现

主程序入口为 `src/main.cpp`。`src/camera/` 管采集，`src/common/` 保存队列与帧结构，`src/inference/` 管 RKNN 与线程池，`src/postprocess/` 管后处理，`src/streaming/` 管 MPP/RTMP，`src/monitoring/` 管性能与延时统计。头文件与对应实现放在一起，通过 CMake 配置头文件搜索路径。

`model/`、`3rdparty/` 与 `build/app` 的位置保持不变。默认资源路径相对于 `build/`；启动脚本会先定位工程根目录，再进入 `build/`。这次目录重排没有将相对模型路径改成依赖某台机器的绝对路径。

## 构建

以下从工程根目录执行。项目依赖 OpenCV、FFmpeg、MPP、OpenCL，以及与板端驱动匹配的 RKNN/RGA 动态库；仓库不包含被忽略的 `.so`，需要沿用板端已验证的库文件。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```

```bash
# 配置 Release 构建，输出仍位于 build/
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
# 编译主程序、离线 benchmark 和诊断工具
cmake --build build -j4
```

目标包括 `app`、`benchmark_postprocess`、`dump_int8`、`dma_probe`、`mpp_fd_probe`、`rknn_eval`。如只需要正式应用与后处理 benchmark，可在配置时指定 `-DBUILD_DIAGNOSTIC_TOOLS=OFF`。RTMP 编译开关仍是 `-DENABLE_RTMP=ON`，默认关闭；运行时也需选择 RTMP 模式。

## 延时测试与复核

```bash
bash scripts/run_latency.sh
python3 tools/summarize_latency.py docs/latency_data/latency_run1.csv docs/latency_data/latency_run2.csv docs/latency_data/latency_run3.csv
```

```bash
# 固定 640×480 YUYV@30、6 线程、8 个缓冲、RKNN fd 输入和 MPP copy 输入
# 三轮独立运行，每轮 1000 帧、排除 100 帧预热；结果写入新的 debug_records/latency_* 目录
bash scripts/run_latency.sh
# 不运行相机，直接从原始纳秒读数重新统计仓库内三轮历史数据
python3 tools/summarize_latency.py docs/latency_data/latency_run1.csv docs/latency_data/latency_run2.csv docs/latency_data/latency_run3.csv
```

短帧冒烟可使用 `bash scripts/run_latency.sh 1 30 5`，不应将其统计与正式 900 帧/轮的结果混用。脚本检查应用退出、错误日志、CSV 数量、帧号、编码成功标志、预热设置及时间顺序；内核 Oops 仍需对测试区间的内核日志单独检查。CPU 预处理对照开关仅作用于 Mat 推理预处理，不能当作整条相机与编码链路完全绕过 RGA 的证明。

## 实验材料与旧路径

| 原位置 | 当前位置 | 说明 |
|---|---|---|
| `eval_data/` | `experiments/eval_data/` | 保留评估图片、标签、压缩包与许可证 |
| `eval_results/` | `experiments/eval_results/` | 精度结果与历史报告 |
| `int8_dumps/` | `experiments/int8_dumps/` | 已提交的离线后处理样本 |
| `video_eval_run/` | `experiments/video_eval_run/` | 历史视频检测图片 |
| `eval_data_exclude_calibration.txt` | `experiments/eval_data/exclude_calibration.txt` | 评估排除清单 |
| `model/main.cpp` | `experiments/legacy/model_main.cpp` | 不参与当前构建的旧示例 |
| `post_process_neon_app.cpp` | `experiments/legacy/post_process_neon_app.cpp` | 未被当前 CMake 使用的历史实现 |
| 根目录的 benchmark 笔记 | `docs/archive/` | 历史性能记录 |
| `README_OrangePi.md` | `docs/usage/README_OrangePi.md` | 历史移植说明 |
| `run_camera_bench.sh`、`kill_camera_app.sh` | `scripts/archive/` | 保留原始实验脚本，非当前推荐入口 |

从 `build/` 运行 `benchmark_postprocess` 时，默认读取 `../experiments/int8_dumps`；指定自己的 dump 时使用 `--data-dir`。`dump_int8` 会设置 `RKNN_INT8_DUMP=1`，新 dump 生成在当前工作目录的 `int8_dumps/`，不会覆盖 `experiments/` 中已提交样本。

归档文档与脚本中的旧路径、旧行号及历史二进制名称按原样保留，不代表当前目录。正式入口与复现方式以本文及根目录 Readme 为准。全部历史数据只移动，不删除；新的运行日志仍在被 Git 忽略的 `debug_records/` 中。
